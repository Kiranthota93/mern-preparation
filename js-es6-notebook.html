Reference notes for ES6+ Features. Read a topic, note the Gotcha, then switch to Coding Questions.

01 Template literals

Simple definition: Backtick-quoted strings that let you interpolate variables directly and span multiple lines without special escape characters.

What ES6 added: before this, building a string with variables meant painful concatenation ('Hi, ' + name + '!'); template literals let you write `Hi, ${name}!` directly, and backticked strings can span multiple lines as-is.

const name = 'Ada';
const greeting = `Hello, ${name}! You are ${2024 - 1815} years old.`;

const multi = `line one
line two`; // real newline, no \n needed
GotchaTagged templates (tag\`text ${value}\`) let a function intercept and process the literal's pieces before the final string is built — this is how libraries like styled-components parse CSS written inside a template literal.

02 Destructuring

Simple definition: ES6's syntax for pulling values out of arrays (by position) or objects (by name) directly into variables.

What ES6 added: a concise, built-in replacement for writing individual const x = obj.x; or const first = arr[0]; lines one at a time.

const [a, b] = [1, 2];             // array — by position
const { name, age } = user;        // object — by name
GotchaFor the full depth of object destructuring (nesting, renaming, defaults), see "Destructuring" under this, objects & prototypes — here it's about recognizing it as one of ES6's headline syntax additions.

03 Spread syntax

Simple definition: The ... operator that expands an array or object into its individual elements/properties.

What ES6 added (ES2018 for objects): a concise way to copy, merge, or pass array/object contents without concat, Object.assign, or apply.

[...[1,2], ...[3,4]];   // [1,2,3,4]
{ ...user, age: 30 };   // shallow-copy + override
GotchaSee "Spread with arrays" / "Object spread" elsewhere in this app for the shallow-copy caveat — the important thing here is recognizing ... as one syntax with two related but distinct uses (arrays vs objects, expand vs collect).

04 Rest parameters

Simple definition: The same ... syntax, but used in a parameter list to collect the remaining arguments into a real array.

What ES6 added: a real-array replacement for the old, awkward arguments object (which isn't a true array and doesn't exist at all in arrow functions).

function sum(...nums) { return nums.reduce((a,b) => a+b, 0); }
sum(1, 2, 3); // 6 — 'nums' is a genuine array
GotchaRest collects (in a parameter list); spread expands (in a call or literal) — same three dots, opposite direction, and it's easy to mix the two names up under pressure.

05 Default parameters

Simple definition: A fallback value a parameter takes when its argument is missing or explicitly undefined.

What ES6 added: before this, defaults required a manual check inside the function body (b = b || 2;) — with its own bug, since that also overrides a deliberately passed 0.

function multiply(a, b = 2) { return a * b; }
multiply(5);       // 10
multiply(5, null); // 0 — default only triggers on undefined, NOT null
GotchaThe old b || 2 pattern breaks on any falsy argument (0, ''); ES6 default parameters correctly trigger only on undefined, which is the whole reason this feature exists as language syntax rather than a userland idiom.

06 Arrow functions

Simple definition: Shorter function syntax that also, distinctively, has no this of its own — it inherits this lexically from its surrounding scope.

What ES6 added: concise syntax AND solved the classic "lost this in a callback" problem that previously required .bind(this) or const self = this; workarounds.

const double = n => n * 2;

const timer = {
  label: 'x',
  start() { setTimeout(() => console.log(this.label), 100); } // inherits start()'s this
};
GotchaFor the full depth on this inheritance and when NOT to use an arrow (never as an object method), see "this in arrow functions" under this, objects & prototypes — the point here is recognizing arrow functions as the ES6 feature that fixed this long-standing pain point.

07 Enhanced object literals

Simple definition: ES6 shorthand for writing object literals — method shorthand, property shorthand, and computed keys, all without the old boilerplate.

Technical definition: Before ES6: { name: name, greet: function() {...} }. After: property shorthand when the variable name matches the key, method shorthand dropping function, and [expr]: for computed keys — all in one literal.

const name = 'Ada';
const key = 'role';

const user = {
  name,                    // shorthand for name: name
  greet() { return 'hi'; }, // shorthand for greet: function(){...}
  [key]: 'admin'            // computed key
};
GotchaMethod shorthand (greet() {}) creates a regular function, not an arrow — it still gets its own this, bound normally by how it's called. Don't assume shorthand syntax changes this behavior; it doesn't.

08 Computed property names

Simple definition: Using [expression] as an object literal's key, so the key itself can be a variable or any computed value.

What ES6 added: before this, a dynamic key required creating the object first, then assigning the property in a separate step (const obj = {}; obj[key] = value;).

const field = 'status';
const obj = { [field]: 'active' }; // { status: 'active' } — built inline
GotchaKeys are always coerced to strings (or left as symbols) — { [{}]: 'x' } silently becomes the key '[object Object]', which is rarely what's intended; use a Map if you genuinely need object keys.

09 Modules

Simple definition: ES6's native way to split code across files, with import/export, replacing older non-standard patterns (global script tags, CommonJS in the browser via bundlers, AMD).

Technical definition: Each ES module has its own scope (nothing leaks to global by accident), is statically analyzed at parse time, and its imports are hoisted and resolved before the module's own code runs — see "ES Modules" under Modules & runtime for the full CJS-vs-ESM comparison.

// math.js
export function add(a, b) { return a + b; }

// app.js
import { add } from './math.js';
GotchaIn the browser, a script must be explicitly marked as a module (<script type="module">) to use import/export at all — plain scripts don't get this syntax, and modules also run in strict mode automatically and defer execution until the DOM is parsed.

10 import

Simple definition: The ES6 keyword for pulling named or default values out of another module.

import { add, subtract } from './math.js'; // named
import Calculator from './calc.js';        // default
import * as math from './math.js';         // namespace object — everything
GotchaStatic import must sit at the top level of a file — never inside an if or a function — because it's resolved before any code runs; use the separate import() function form (see "Dynamic imports") for conditional, runtime-decided loading.

11 export

Simple definition: The ES6 keyword that marks a value as available for other modules to import.

export const PI = 3.14;               // named export, attached to a declaration
export { add, subtract };              // named exports, listed separately
export default class Calculator {}     // the module's one default export
GotchaA module can have unlimited named exports but at most one default — see "Named exports" / "Default exports" for the practical difference in how each is imported.

12 Named exports

Simple definition: Exports referred to by their exact name — a module can have as many as it wants, and importers must use (or explicitly rename) that same name.

// utils.js
export const add = (a, b) => a + b;
export const subtract = (a, b) => a - b;

// app.js
import { add, subtract as minus } from './utils.js'; // rename with 'as'
GotchaNamed imports must be wrapped in { } and must match an actual exported name — import add from './utils.js' (no braces) is trying to import a default export that doesn't exist here, and silently gives undefined rather than an error in some setups.

13 Default exports

Simple definition: A module's single "main" export, imported without needing curly braces and importable under any name the importer chooses.

// Calculator.js
export default class Calculator { /* ... */ }

// app.js — the imported name doesn't have to match anything
import Calc from './Calculator.js';
import MyCalculator from './Calculator.js'; // also valid, same module
GotchaBecause a default import's local name is entirely up to the importer, typos are never caught — import Calclator from './Calculator.js' (misspelled) works fine syntactically, unlike a named import typo, which fails immediately since it must match the real exported name.

14 Optional chaining

Simple definition: ?. safely reads a nested property, returning undefined instead of throwing if something along the way is null/undefined.

What it replaced: long, repetitive guard chains like user && user.profile && user.profile.city.

user.profile?.city;   // undefined instead of a TypeError, if profile is missing
user.getName?.();     // safe optional call
user.tags?.[0];        // safe optional index
GotchaIt only guards against null/undefined — it won't protect you from other genuine errors deeper in an expression, and it can't be used on the left side of an assignment.

15 Nullish coalescing

Simple definition: ?? provides a fallback, but only when the left side is null or undefined — unlike ||, it doesn't treat 0, '', or false as "missing".

const count = 0;
count || 10;  // 10 — bug: 0 is falsy, treated as missing
count ?? 10;  // 0  — correct: 0 is a real, valid value
GotchaYou cannot mix ?? directly with || or && without parentheses — a || b ?? c is a SyntaxError, forcing you to make the intended precedence explicit.

16 Logical assignment operators

Simple definition: ||=, &&=, and ??= combine a logical check with an assignment, only assigning when the check passes.

Technical definition: a ||= b assigns b to a only if a is currently falsy; a &&= b assigns only if a is truthy; a ??= b assigns only if a is null/undefined. Crucially, all three short-circuit — if the condition fails, the right-hand side isn't even evaluated, and no assignment happens at all.

let config = { retries: 0 };
config.retries ||= 3; // 3 — 0 is falsy, so it WAS reassigned (probably not intended!)

let config2 = { retries: 0 };
config2.retries ??= 3; // 0 — stays 0, since 0 is not null/undefined (correct)
GotchaThe short-circuiting matters for more than performance — if the right-hand side is a setter with side effects (or an expensive call), ??= guarantees that code never runs at all when the left side is already non-nullish, unlike writing out a = a ?? expensiveCall() naively without checking it's actually equivalent.

17 for...of

Simple definition: A loop that iterates over the values of any iterable — arrays, strings, Maps, Sets, and any custom object implementing the iterator protocol.

for (const value of [10, 20, 30]) console.log(value); // 10, 20, 30 — values
for (const char of 'hi') console.log(char);            // 'h', 'i'

The essential contrast — for...of vs for...in: for...of gives you values from an iterable. for...in gives you enumerable keys (as strings) from any object, including inherited ones, and should basically never be used on arrays.

const arr = [10, 20, 30];
for (const x of arr) console.log(x);      // 10, 20, 30 — the values
for (const i in arr) console.log(typeof i, i); // 'string' '0', 'string' '1', 'string' '2' — STRING indices!
GotchaUsing for...in on an array gives you string indices, not numbers — and it will also pick up any enumerable properties added to Array.prototype by other code. Use for...of (values) or .forEach/.entries() (index+value) for arrays instead.

18 Symbols

Simple definition: A primitive type whose every value is guaranteed unique — used mainly as "invisible", collision-proof object keys.

Technical definition: Symbol('description') creates a value that is never === to any other symbol, even one with the identical description. Symbol-keyed properties are skipped by Object.keys, for...in, and JSON.stringify — they only show up via Object.getOwnPropertySymbols.

const id = Symbol('id');
const user = { name: 'Ada', [id]: 123 };
Object.keys(user);       // ['name'] — the symbol key is invisible here
JSON.stringify(user);    // '{"name":"Ada"}' — symbol silently dropped

Symbol('x') === Symbol('x'); // false — always unique, even with the same description
GotchaSymbol.iterator is a "well-known symbol" built into the language — it's the exact key JavaScript looks for to decide whether something is iterable, which is what makes for...of, spread, and destructuring work on arrays, strings, Maps, and Sets (see "Iterators").

19 Iterators

Simple definition: An object with a .next() method that hands out one value at a time, marking when it's done.

Technical definition: An object is iterable if it has a [Symbol.iterator]() method returning an iterator — an object whose .next() returns { value, done } each call, until done is true. This shared protocol is what for...of, spread, and destructuring all rely on.

const arr = [10, 20];
const it = arr[Symbol.iterator]();
it.next(); // { value: 10, done: false }
it.next(); // { value: 20, done: false }
it.next(); // { value: undefined, done: true }
GotchaImplementing [Symbol.iterator]() on your own custom object automatically makes it work with for...of, spread, and destructuring — you get native-feeling syntax support for free, without those features knowing anything specifically about your object's structure.

20 Generators

Simple definition: A function* that can pause with yield and resume later — the easy way to build an iterator without hand-writing a .next() method.

Technical definition: Calling a generator function returns a generator object (which is itself an iterator) without running the body. Each .next() call runs until the next yield, returns that value, and pauses exactly there until the next .next() call.

function* range(start, end) {
  for (let i = start; i < end; i++) yield i;
}
for (const n of range(1, 4)) console.log(n); // 1, 2, 3

function* naturals() { let n = 1; while (true) yield n++; } // infinite, but LAZY —
// nothing runs until .next() is actually called, so this is perfectly safe to define
GotchaGenerators are lazy by nature — this is precisely what makes an "infinite" generator safe to write: each value is computed only the instant it's requested, never all at once upfront.

21 Map

Simple definition: A key-value collection like an object, but with real advantages: any type can be a key, insertion order is preserved, and it has a built-in .size.

Map vs Object — the real comparison: object keys are always coerced to strings/symbols; a Map key can be anything — including an object or a function. Objects don't guarantee iteration order in every edge case; a Map always iterates in insertion order. Checking size means Object.keys(obj).length for an object, versus a direct .size property on a Map.

const objKey = { role: 'admin' };
const m = new Map();
m.set(objKey, 'has extra permissions');
m.set('plain string key', 'ok');

m.get(objKey); // 'has extra permissions' — the OBJECT itself is the key
m.size;         // 2

for (const [key, value] of m) console.log(key, value); // directly iterable
GotchaAn object literal cannot use another object as a genuinely distinct key — { [objKey]: 'x' } coerces objKey to the useless string '[object Object]'. This is exactly the case a Map was designed to solve.

22 Set

Simple definition: A collection that only ever holds unique values — adding a duplicate is silently a no-op.

const nums = new Set([1, 2, 2, 3]);
nums.size;        // 3 — the duplicate 2 was never actually added
nums.has(2);       // true
nums.add(2);       // no-op, already present

const unique = [...new Set([1, 2, 2, 3])]; // [1, 2, 3] — the standard dedupe idiom
GotchaSet uses ===-like equality (technically "SameValueZero"), so two structurally-identical but separately-created objects are still treated as different members — new Set([{}, {}]).size is 2, not 1, because they're different references.

23 WeakMap

Simple definition: Like Map, but its keys must be objects and are held weakly — that reference alone doesn't stop garbage collection.

Technical definition: WeakMap keys must be objects (never primitives), aren't iterable, and have no .size — you can only interact with a specific object you already have a reference to.

let user = { name: 'Ada' };
const metadata = new WeakMap();
metadata.set(user, { lastSeen: Date.now() });

user = null; // no other references — the WeakMap entry can now be garbage collected too
GotchaThe missing iteration/.size is deliberate, not a limitation to work around — see "WeakMap/WeakSet use cases" under Advanced JavaScript for why exposing that would be inherently unpredictable given when GC actually runs.

24 WeakSet

Simple definition: Like Set, but its members must be objects, held weakly — not iterable, no .size.

Why it is used: tracking "has this specific object been seen/processed?" without preventing that object from being garbage collected once nothing else references it.

const processed = new WeakSet();
function process(obj) {
  if (processed.has(obj)) return; // already handled
  processed.add(obj);
  // ... do the real work
}
GotchaBecause it can't be iterated, a WeakSet is only useful for membership checks (.has()) on objects you already have a direct reference to — you can never ask it "what's currently in you?", which is the deliberate trade for allowing garbage collection.

10 questions, ordered easy → hard. Try each one before revealing the answer.

Q1easy

// template literals

Rewrite this using a template literal:

const msg = 'Hello, ' + name + '! You have ' + count + ' items.';

Show answer 
const msg = `Hello, ${name}! You have ${count} items.`;

Any valid expression can go inside ${...} — not just plain variables, e.g. ${count + 1} or ${user.name.toUpperCase()} both work directly.

Q2easy

// for...of vs for...in

What does each loop log, and why are they different?

const arr = [10, 20, 30];
for (const x of arr) console.log(x);
for (const i in arr) console.log(i);

Show answer

First loop logs 10, 20, 30 — the actual values. Second loop logs "0", "1", "2" — the keys, as strings. for...of iterates values from an iterable; for...in iterates enumerable keys from any object, and on an array that means its string indices, not its values — a common source of confusion.

Q3easy

// Set dedupe

Write a one-liner that removes duplicates from [1, 2, 2, 3, 3, 3].

Show answer 
const unique = [...new Set([1, 2, 2, 3, 3, 3])];
// [1, 2, 3]

A Set can only ever hold unique values — constructing one from the array automatically drops duplicates, then spreading it back into [...] gives you a plain array again.

Q4medium

// named vs default export

What's wrong with this import, given how math.js exports things?

// math.js
export const add = (a, b) => a + b;

// app.js
import add from './math.js';
console.log(add(2, 3));

Show answer

add logs as undefined, and calling it throws a TypeError. math.js exports add as a named export, but app.js is trying to import it as the default export (no curly braces means "give me the default"). Since there is no default export in math.js, the import silently resolves to undefined. Fix: import { add } from './math.js';

Q5medium

// logical assignment falsy trap

What's the bug in this config-defaulting code?

function setRetries(config) {
  config.retries ||= 3; // default to 3 if not set
  return config;
}
console.log(setRetries({ retries: 0 }).retries);

Show answer

Logs 3, but the caller explicitly set retries: 0 — meaning "don't retry at all", a perfectly valid value — and it got silently overwritten. ||= assigns whenever the current value is falsy, and 0 is falsy. Fix: use ??= instead, which only assigns on null/undefined, correctly leaving a deliberate 0 alone: config.retries ??= 3;

Q6medium

// Map with object keys

Why does this Object-based approach fail, and how does a Map fix it?

const key1 = { id: 1 };
const key2 = { id: 2 };
const store = {};
store[key1] = 'first';
store[key2] = 'second';
console.log(Object.keys(store));

Show answer

Logs ['[object Object]'] — just one key. Object keys are always coerced to strings, and both key1 and key2 coerce to the exact same string, '[object Object]', so the second assignment overwrites the first.

const store = new Map();
store.set(key1, 'first');
store.set(key2, 'second');
store.get(key1); // 'first' — the actual object reference is the key, no coercion
Q7medium

// generator laziness

Is it safe to define this generator? What does the loop actually log?

function* naturals() {
  let n = 1;
  while (true) yield n++;
}

for (const n of naturals()) {
  if (n > 3) break;
  console.log(n);
}

Show answer

Perfectly safe — logs 1, 2, 3, then stops. Generators are lazy: while (true) never actually runs an infinite loop all at once. Each iteration of the for...of calls .next() exactly once, advancing the generator by a single yield, and break simply stops requesting more.

Q8hard

// WeakMap prevents leak

Rewrite this cache using WeakMap so that objects can still be garbage collected once nothing else references them.

const cache = new Map();
function getMetadata(obj) {
  if (!cache.has(obj)) cache.set(obj, computeMetadata(obj));
  return cache.get(obj);
}

Show answer 
const cache = new WeakMap(); // only this line changes
function getMetadata(obj) {
  if (!cache.has(obj)) cache.set(obj, computeMetadata(obj));
  return cache.get(obj);
}

A regular Map holds its keys with a strong reference, so every object ever passed to getMetadata stays alive forever purely because it's a cache key — a silent memory leak. WeakMap holds keys weakly, so once nothing else in the program references a given object, it (and its cache entry) becomes eligible for garbage collection normally, exactly as if it had never been cached.

Q9hard

// custom iterable

Make this range object work with for...of and spread, by implementing the iterator protocol.

const range = { start: 1, end: 4 };
// desired: for (const n of range) ... logs 1, 2, 3
// desired: [...range] === [1, 2, 3]

Show answer 
const range = {
  start: 1,
  end: 4,
  [Symbol.iterator]() {
    let current = this.start;
    const end = this.end;
    return {
      next() {
        if (current < end) return { value: current++, done: false };
        return { value: undefined, done: true };
      }
    };
  }
};

for (const n of range) console.log(n); // 1, 2, 3
[...range]; // [1, 2, 3]

Implementing [Symbol.iterator]() — returning an object with a .next() that yields { value, done } — is exactly the protocol for...of and spread both rely on. Once it's there, any built-in syntax that consumes iterables works on this custom object automatically, for free.

Q10hard

// optional chaining does not guard everything

Does ?. prevent an error here? Why or why not?

function getCity(user) {
  return user?.address.city; // note: only ONE ?. 
}
getCity({ address: null });

Show answer

No — this still throws a TypeError. user?.address is safely guarded (returns undefined if user is nullish), but the result of that (null, since address genuinely IS null here) is then accessed with a plain .city, which is NOT optional-chained. ?. only guards the specific link it's placed on — every step in a chain that might be nullish needs its own ?.: user?.address?.city.
