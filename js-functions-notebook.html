00 Why functions matter

Simple definition: A function is a reusable block of code that performs a task and can be called again.

Technical definition: In JavaScript, a function is a callable value with its own execution context, local scope, parameters, and optional return value.

Why it is used: Functions remove duplication, organize behavior, and let you reuse logic with different inputs.

When to use: Use functions for calculations, validation, handlers, API code, and behavior that must run multiple times.

When not to use: Do not create tiny one-off functions that only hide a single line of code; avoid mixing unrelated logic in one large function.

How it works internally: Each call creates a fresh execution context, assigns arguments to parameters, runs the body, and then removes the frame from the call stack.

function greet(name) {
  return `Hello, ${name}!`;
}
console.log(greet("Ada")); // Hello, Ada!
GotchaFunctions are not special magic — they are reusable units of work. The big differences are how they are created and how this is bound.

01 Function declarations

A named function created with the function keyword.

function greet(name) {
  return `Hello, ${name}!`;
}
  • Hoisted — the whole function moves to the top of its scope, so you can call it before it appears.
  • Best for named, reusable logic.
GotchasayHi() works even if function sayHi(){} is written lower down.

02 Function expressions

A function assigned to a variable (often anonymous).

const square = function (n) {
  return n * n;
};
  • Not hoisted — usable only after the defining line.
  • Treats the function as a value you can store and pass around.
GotchaCalling it before its line throws Cannot access 'square' before initialization.

03 Arrow functions

Shorter syntax for function expressions (ES6).

const double = n => n * 2;        // implicit return
const add = (a, b) => a + b;      // multiple params need ()
const makeUser = id => ({ id });  // return object → wrap in ()
  • No own this — inherits it from the surrounding scope.
  • No arguments object; can't be used with new.
Gotchaid => { id } returns undefined (that's a code block). Use id => ({ id }).

04 Parameters and arguments

  • Parameters = names in the definition.
  • Arguments = actual values passed in.
function fullName(first, last) {   // parameters
  return `${first} ${last}`;
}
fullName("Ada", "Lovelace");       // arguments
GotchaThe arguments object is array-like, not a real array — no .map(). (Arrows don't even have it.)

05 Default parameters

A fallback used when the argument is missing or undefined.

function multiply(a, b = 2) {
  return a * b;
}
multiply(5);      // 10
multiply(5, 3);   // 15
GotchaDefault triggers on undefined but not on null — multiply(5, null) gives 0.

06 Rest parameters

Collects any number of remaining arguments into a real array. Uses ....

function sum(...numbers) {
  return numbers.reduce((t, n) => t + n, 0);
}
sum(1, 2, 3, 4);   // 10
GotchaOnly one rest parameter allowed, and it must be last.

07 Spread syntax

Same ..., but it expands an array/object into pieces.

const merged = [...[1, 2], ...[3, 4]];   // [1,2,3,4]
const clone  = { ...user, age: 30 };     // copy + override
const max    = Math.max(...[4, 9, 2]);   // 9
GotchaSpread makes a shallow copy — nested objects are still shared by reference. Rest collects, spread expands.

08 Higher-order functions

A function that takes a function as an argument and/or returns a function.

function applyTwice(fn, value) {
  return fn(fn(value));
}
applyTwice(n => n + 3, 0);   // 6

map, filter, reduce, setTimeout are all higher-order.

09 Callback functions

A function passed into another to be called later.

[1, 2, 3].forEach(item => console.log(item));   // arrow is the callback
setTimeout(() => console.log("done"), 1000);   // runs after 1s
GotchaDeeply nested callbacks = "callback hell". Promises / async-await solve it.

10 First-class functions

In JS, functions are values — like numbers or strings.

const f = () => "hi";      // store in a variable
const list = [f];             // put in an array
function run(fn) { fn(); }    // pass as an argument

This property is what makes callbacks and higher-order functions possible.

11 Closures

A function remembers the variables from where it was created — even after that outer function returned.

function makeCounter() {
  let count = 0;          // private
  return () => ++count;
}
const counter = makeCounter();
counter();  // 1
counter();  // 2  ← count persists
GotchaClassic loop bug: var in a loop shares one binding (prints 3,3,3); let makes a new one each time (0,1,2).

12 IIFE

Immediately Invoked Function Expression — runs the instant it's defined.

(function () {
  console.log("runs immediately");
})();

(() => {
  const secret = 42;   // private to this block
})();
GotchaNeeds the wrapping () — a bare function(){}() is a syntax error. Mostly replaced by modules today.

13 Recursion

A function that calls itself until it hits a base case.

function factorial(n) {
  if (n <= 1) return 1;          // base case — stops it
  return n * factorial(n - 1);   // recursive case
}
factorial(5);   // 120
GotchaNo base case (or never reaching it) → Maximum call stack size exceeded.

14 Pure functions

Same input → same output, and no side effects (doesn't touch outside state).

const add = (a, b) => a + b;            // PURE

let total = 0;
const addImpure = n => (total += n);    // IMPURE — mutates outside

Pure functions are predictable, testable, cacheable — a core idea in React and functional programming.

15 Currying

Turning a multi-argument function into a chain of single-argument functions.

const add = a => b => c => a + b + c;
add(1)(2)(3);   // 6

const add5 = add(5);   // partially applied
add5(10)(20);         // 35

Lets you pre-fill some arguments now and supply the rest later.

16 this, call / apply / bind

this depends on how a function is called (arrows are the exception — they inherit it).

function greet() { return `Hi, ${this.name}`; }
const person = { name: "Ada" };

greet.call(person);          // "Hi, Ada"  — args listed
greet.apply(person);         // "Hi, Ada"  — args as array
const bound = greet.bind(person);   // new function, this fixed
bound();                     // "Hi, Ada"
GotchaArrow functions ignore call/apply/bind for this — they always use the enclosing scope.

Q1easy

// declaration vs expression

Which of these two calls works, and which throws? Why?

hi();
bye();
function hi() { console.log("hi"); }
const bye = () => console.log("bye");
Show answer

hi() works — function declarations are hoisted. bye() throws Cannot access 'bye' before initialization — the arrow is a const expression, not hoisted.

Q2easy

// arrow returning an object

Why does this print undefined, and how do you fix it?

const make = id => { id: id };
console.log(make(5));
Show answer

The { } is read as a function body, not an object, so nothing is returned → undefined. Fix by wrapping the object in parentheses: const make = id => ({ id });

Q3easy

// default parameters

Predict all three outputs:

function f(a, b = 10) { return a + b; }
console.log(f(5));
console.log(f(5, 2));
console.log(f(5, undefined));
Show answer

15, 7, 15. Passing undefined explicitly still triggers the default. (Passing null would give 5, since null does not.)

Q4easy

// rest parameters

Write max(...nums) that returns the largest number passed.

Show answer 
function max(...nums) {
  return Math.max(...nums);
}
max(3, 9, 2);   // 9

Rest ...nums collects the args into an array; spread ...nums expands it back out for Math.max.

Q6medium

// callbacks & map

Implement your own myMap(arr, cb) that behaves like Array.map.

Show answer 
function myMap(arr, cb) {
  const out = [];
  for (let i = 0; i < arr.length; i++) {
    out.push(cb(arr[i], i, arr));
  }
  return out;
}
myMap([1, 2, 3], x => x * 10);   // [10, 20, 30]
Q7medium

// closures

Write makeCounter() so that each returned counter keeps its own private count. Then show two counters are independent.

Show answer 
function makeCounter() {
  let count = 0;
  return () => ++count;
}
const a = makeCounter();
const b = makeCounter();
a(); a();   // 1, 2
b();        // 1  ← independent, its own count

Each call to makeCounter creates a fresh count that its returned function closes over.

Q8medium

// closure loop bug

What does this print, and how do you make it print 0, 1, 2?

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
Show answer

It prints 3, 3, 3. All three callbacks share the one var i, which is 3 by the time they run. Fix: change var to let — let creates a new binding of i per iteration → 0, 1, 2.

Q9medium

// recursion

Write a recursive factorial(n). What is factorial(4)?

Show answer 
function factorial(n) {
  if (n <= 1) return 1;        // base case
  return n * factorial(n - 1);
}
factorial(4);   // 24  (4*3*2*1)
Q10medium

// pure vs impure

Which function is pure, and why?

// A
const addTax = p => p * 1.1;

// B
let rate = 1.1;
const addTax2 = p => p * rate;
Show answer

A is pure — same input always gives the same output, no outside dependency. B is impure-ish: it depends on the external rate, so its result can change without its input changing. Pure functions don't read mutable outside state.

Q11hard

// currying

Write a curried add(a)(b)(c). Then create add10 that always adds 10 as the first number.

Show answer 
const add = a => b => c => a + b + c;
add(1)(2)(3);        // 6

const add10 = add(10);
add10(5)(5);         // 20

Each call returns the next function until all three arguments are collected, then it computes.

Q12hard

// this & bind

Why does setTimeout log undefined, and how do you fix it two ways?

const user = {
  name: "Ada",
  greet() {
    setTimeout(function () {
      console.log(this.name);
    }, 100);
  }
};
user.greet();
Show answer

The plain function callback gets its own this (not user), so this.name is undefined.

Fix 1 — arrow function (inherits this from greet):

setTimeout(() => console.log(this.name), 100);

Fix 2 — bind:

setTimeout(function () {
  console.log(this.name);
}.bind(this), 100);
