01 Variables: var, let, const

Three ways to declare a variable. They differ in scope and whether they can be reassigned.

var a = 1;    // function-scoped, old style — avoid
let b = 2;    // block-scoped, can be reassigned
const c = 3;  // block-scoped, cannot be reassigned
  • const is your default. Use let only when you must reassign.
  • const blocks reassignment, but object/array contents can still change.
Gotchaconst arr = [1]; arr.push(2) works — you didn't reassign arr, only mutated it.

02 Data types

JS has 7 primitives plus objects.

  • Primitives: string, number, boolean, null, undefined, bigint, symbol.
  • Everything else — arrays, functions, dates — is an object.
typeof "hi"      // "string"
typeof 42        // "number"
typeof [1,2]     // "object"  (arrays are objects)
typeof null      // "object"  ← historic bug
Gotchatypeof null returns "object" — a famous language bug, kept for compatibility.

03 Type coercion

JS automatically converts types when you mix them. This is the source of many surprises.

"5" + 1    // "51"   (number → string, concatenation)
"5" - 1    // 4      (string → number, subtraction)
true + 1   // 2      (true → 1)
[] + []    // ""     (both become empty strings)
Gotcha+ means concatenate if either side is a string; every other math operator forces numbers.

04 == vs ===

== compares after coercing types. === compares value and type — no coercion.

0 == ""        // true   (both coerce to falsy)
0 === ""       // false  (number vs string)
1 == "1"       // true
1 === "1"      // false
GotchaAlways use ===. The only common exception: x == null checks for both null and undefined at once.

05 null vs undefined

  • undefined — a variable declared but not assigned; JS gives it to you.
  • null — an intentional "empty" value; you assign it deliberately.
let x;              // undefined
let y = null;       // null — "I chose to leave this empty"
typeof undefined   // "undefined"
typeof null        // "object"
Gotchanull == undefined is true, but null === undefined is false.

06 Truthy / falsy

Every value is either "truthy" or "falsy" when used in a condition. Memorize the falsy list — everything else is truthy.

// The 8 falsy values:
false, 0, -0, 0n, "", null, undefined, NaN

if ([]) { ... }   // runs! empty array is truthy
if ({}) { ... }   // runs! empty object is truthy
GotchaEmpty array [] and empty object {} are truthy. Only the 8 values above are falsy.

07 Operators

  • Arithmetic: + - * / % **
  • Logical: && (and), || (or), ! (not)
  • Nullish coalescing: ?? — fallback only for null/undefined
  • Optional chaining: ?. — safely access nested properties
0 || "default"   // "default"  (0 is falsy)
0 ?? "default"   // 0          (0 is not null/undefined)
user?.address?.city  // undefined instead of a crash
GotchaUse ?? not || when 0 or "" are valid values you want to keep.

08 Scope

Scope = where a variable is accessible.

  • Global — declared outside any function/block.
  • Function — var is limited to the function it's in.
  • Block — let/const are limited to the nearest { }.
{
  let a = 1;
  var b = 2;
}
console.log(b);  // 2   (var ignores the block)
console.log(a);  // ReferenceError (let is block-scoped)
Gotchavar leaks out of blocks; let/const don't. Another reason to avoid var.

09 Hoisting

Declarations are "moved" to the top of their scope before code runs.

  • function declarations are fully hoisted — callable before their line.
  • var is hoisted but initialized as undefined.
  • let/const are hoisted but not initialized — the "temporal dead zone".
console.log(a);  // undefined (var hoisted, not assigned yet)
var a = 5;

console.log(b);  // ReferenceError (TDZ)
let b = 5;
GotchaAccessing a let/const before its line throws — it's not undefined, it's an error (TDZ).

10 Template literals

Backtick strings that support interpolation and multi-line text.

const name = "Ada";
`Hello, ${name}!`          // "Hello, Ada!"
`Sum: ${2 + 3}`            // "Sum: 5"  (any expression)
`line one
line two`                  // real line break
GotchaUse backticks ` `, not quotes. ${ } can hold any expression, not just variables.

11 Control flow

Decide which code runs.

if (score >= 90) grade = "A";
else if (score >= 80) grade = "B";
else grade = "C";

// ternary — a compact if/else that returns a value
const msg = age >= 18 ? "adult" : "minor";

switch (day) {
  case "Sat":
  case "Sun": type = "weekend"; break;
  default: type = "weekday";
}
GotchaForgetting break in a switch causes "fall-through" — it keeps running the next cases.

12 Loops

Repeat code. Pick the loop that fits the data.

for (let i = 0; i < 3; i++) { ... }        // classic counter

for (const item of [10, 20]) { ... }        // values of an array

for (const key in { a: 1 }) { ... }        // keys of an object

[1,2,3].forEach(n => console.log(n));       // array method

while (condition) { ... }                   // until condition is false
Gotchafor...of = values (arrays). for...in = keys (objects). Mixing them up is a classic mistake.

Try each one in your head or in the browser console (F12) first. Then click Show answer to check. Predicting output trains you far faster than reading.

Q1easy

// variables & const

Will this throw an error? Why or why not?

const nums = [1, 2, 3];
nums.push(4);
console.log(nums);
Show answer

No error. Output: [1, 2, 3, 4]. const only prevents reassigning nums. Mutating the array it points to is fine. It would throw only on nums = [...].

Q2easy

// type coercion

Predict each output:

console.log("5" + 3);
console.log("5" - 3);
console.log(true + true);
Show answer

"53" (+ with a string concatenates), 2 (- forces numbers), 2 (true becomes 1). Only + concatenates; all other math operators coerce to numbers.

Q3easy

// == vs ===

What does each print?

console.log(0 == "");
console.log(0 === "");
console.log(null == undefined);
console.log(null === undefined);
Show answer

true, false, true, false. == coerces before comparing; === requires same type. null and undefined are loosely equal only to each other.

Q4medium

// truthy / falsy

Which of these if blocks run?

if ([])        console.log("A");
if ("")        console.log("B");
if ("0")       console.log("C");
if (0)         console.log("D");
Show answer

A and C run. [] is truthy (empty array is still an object). "0" is a non-empty string → truthy. "" and 0 are both on the falsy list.

Q5medium

// nullish coalescing vs OR

What's the difference in output here?

const count = 0;
console.log(count || 10);
console.log(count ?? 10);
Show answer

10 then 0. || falls back on any falsy value (including 0). ?? falls back only on null/undefined, so it keeps the valid 0.

Q6medium

// hoisting

Predict the output (or error) of each:

console.log(a);
var a = 1;

console.log(b);
let b = 2;
Show answer

First logs undefined — var a is hoisted but not yet assigned. Second throws ReferenceError — let b is in the temporal dead zone until its line executes.

Q7medium

// scope

What does this log?

{
  var x = 10;
  let y = 20;
}
console.log(x);
console.log(y);
Show answer

10, then a ReferenceError on y. var ignores block scope and leaks out; let is confined to the { } block.

Q8medium

// switch fall-through

What is result when x = 1?

let result = "";
switch (x) {
  case 1: result += "a";
  case 2: result += "b"; break;
  case 3: result += "c";
}
Show answer

"ab". Case 1 has no break, so it falls through into case 2 and runs it too, then break stops it. Case 3 never runs.

Q9medium

// loops: for...of vs for...in

What does each loop print for const arr = ["a", "b"]?

for (const v of arr) console.log(v);
for (const k in arr) console.log(k);
Show answer

for...of prints the values: "a", "b". for...in prints the keys/indexes: "0", "1" (as strings). Use of for array values.

Q10hard

// coercion + operators combined

Predict every line — this one catches almost everyone:

console.log(1 + "2" + 3);
console.log(1 + 2 + "3");
console.log("5" * "2");
console.log(null + 1);
console.log(undefined + 1);
Show answer

"123" (left-to-right: 1+"2"→"12", then +3→"123").
"33" (1+2=3 first, then +"3"→"33").
10 (* coerces both strings to numbers).
1 (null→0).
NaN (undefined→NaN, and any math with NaN is NaN).
